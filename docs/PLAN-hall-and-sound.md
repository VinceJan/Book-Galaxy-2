# 计划：现场「大厅」模式 + 生成式声音层（核心稳定后再开工）

决赛日：2026-10-24。品味标准与夜班馆员相同：纸色 #efe7d6、朱印红 #c8361d、墨色 #1d1a16，每类内容一种字体（Noto Serif SC 用于展示，LXGW WenKai 用于馆员的声音，IBM Plex Mono 用于数据，Cormorant Garamond 斜体用于外文书名）。不用霓虹，不用粒子特效。

## 1. 大厅模式 `#/hall`（大屏）+ `#/join/<room>`（手机）
- **画面**：大屏是一张「夜班阅览室」长桌的俯视图。每位评委就是桌上的一张借书卡：扫码加入时，卡片从边缘滑入，写上匿名代号（例如「第 3 号读者」）。评委提交纸条后，大屏上逐字写出这张卡收到的回信摘要（书名 + 一句真实摘录），并盖上「唤醒 / 借出」的章。
- **桥**：两位参与者拿到的书向量相似度 > 0.45 时，两张卡之间长出一缕菌丝墨线（复用档案页的笔触），旁边用 Mono 字体标注共享主题，只用真实的 `sharedThemes` 或相似度数值。这就是“人与人之间的偶遇”。
- **手机端**：一张输入纸条的卡片和 6 个情境词。检索在手机上本地运行（与主站同一套模型和向量）。在线时把 `{bookId, note 前 40 字, sim}` 发到房间；断线时只在本机显示回信。
- **实时后端**：选 **PartyKit**（Cloudflare Durable Object，一个房间一个对象，部署用 `npx partykit deploy`；仓库 `party/hall.ts`）。消息有 join / note / letter / leave，服务端只做广播，外加最近 50 条的内存快照。备选是 Supabase Realtime broadcast channel，两者在 `src/hall/transport.ts` 下共用同一个接口。
- **离线兜底**：`?room=local` 时在同一台设备上用 BroadcastChannel 模拟多人。大屏也可以切成「单机演示」：主持人在大屏上直接写纸条，或者回放一份录好的真实会话 JSON，并明确标注「回放」。
- **QR**：用本地生成的 SVG 二维码（`qrcode-generator`，约 20KB），放在大屏右下角，印在一张小借书卡上。
- **风险**：现场 Wi-Fi 不可靠（手机检索在本地完成，只同步很小的 JSON，二维码同时支持 4G）；模型下载约 120MB 对手机太重 → hall/join 默认先用字面检索，同时后台载入模型，或者预备一个更小的向量模型（待评估）。另外需要防止有人刷屏或写不当内容：纸条在大屏只显示前 40 字，主持人可以一键隐藏。

## 2. 生成式声音层（默认静音）
- 只有一个开关「♪ 书库的声音」，放在页眉右侧，用 Mono 小字，默认关闭，设置存进 localStorage。
- **映射**（全部来自真实数据）：地域 → 调式的根音（东亚用五声宫调，欧洲用多利亚调，美洲用混合利底亚调……全部固定在 A 小调相近的音域，保证和谐）；年份 → 音区（越古老越低）；关系类型 → 音色（潮汐 = 柔和正弦 pad，余烬 = 拨弦衰减，暗河 = 低通噪声加低音，裂隙 = 轻微失谐的钟声）；冷门度 → 混响长度（越冷门越远、越空）。
- **触发**：盖章时一个短促的「纸」音（滤波噪声，40ms），回信写完时响起该书的三音动机；档案页里每长出一缕菌丝，奏一个对应关系类型的音。在大厅模式里，每次有新参与者的书被唤醒，就加一个音，整体最多 6 个声部，音量很低。
- **实现**：只用 Web Audio，不引入 Tone.js；`src/sound.ts` 不超过 200 行，严格遵守 prefers-reduced-motion 和静音开关。
- 先看看 `/workspace/BookGalaxy-extra/book-score` 里有没有可以复用的映射思路；它的界面不要复用（被判丑）。
